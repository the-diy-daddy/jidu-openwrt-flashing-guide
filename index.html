Identify your router's family from the rear hardware label: 6101, 6j01, or 6j11. Flashing the wrong family image can permanently brick the bootloader.

Check the version in the stock admin panel. 6101 supports all firmwares; 6j01 requires R3.2 or older; 6j11 requires R3.2.6 or older for software-only flashing.

Attempt the administrative password trick first. If the router rejects SSH login, fall back to the breeze.sh script or a WebUI downgrade.

Write the verified OpenWrt sysupgrade image via SSH, or connect a 3.3V USB-to-TTL serial adapter to flash over UART where required.

04In-Depth Flashing & Configuration Documentation

1. Gaining SSH Access (Password Trick & breeze.sh)

Before flashing OpenWrt over the network, you must unlock root shell access on the stock firmware. On supported firmware builds (such as R3.2.6 or earlier for 6j01/6j11 models, and all builds on 6101), the stock web interface passes administrative parameters that can be leveraged to enable Dropbear SSH.

  • Prerequisites: A PC connected via Ethernet to LAN Port 1, a terminal client (Windows Terminal, PowerShell, or Linux Bash), and your router's default gateway IP (typically 192.168.29.1).
  • Password Trick Method: Log into the stock WebUI, inspect the administrative password/diagnostic request, and authenticate over SSH using the derived root credentials (ssh root@192.168.29.1).
  • breeze.sh Exploit Fallback: If the stock firmware rejects direct SSH login, the breeze.sh script automates command injection through the local management API or configuration backup/restore routine to spawn a temporary Telnet or SSH daemon on port 22.
  • Flashing via Sysupgrade: Once logged in as root, back up your factory ART/calibration partitions if applicable, transfer the matching OpenWrt sysupgrade.bin image to the /tmp directory using scp, verify its SHA256 checksum, and execute sysupgrade -n /tmp/openwrt-sysupgrade.bin. Do not power off the router during the 3-minute write cycle.

2. Serial UART Recovery & Direct Flashing

Routers running newer patched stock firmwares (above R3.2.6 on 6j01/6j11) block software-based SSH exploits and firmware downgrades. In these cases, flashing requires direct serial access to the U-Boot bootloader via the PCB's UART header.

  • Required Hardware: A 3.3V USB-to-TTL serial adapter (CP2102, FT232RL, or CH340G), female-to-male jumper wires, and a TFTP server running on your computer (such as Tftpd64 on Windows or dnsmasq on Linux).
  • Pinout Wiring: Connect GND to GND, Router TX to Adapter RX, and Router RX to Adapter TX. Never connect the 3.3V or 5V VCC pin while the router is powered by its DC barrel adapter, as back-feeding voltage can damage the USB controller or router SoC.
  • U-Boot TFTP Transfer: Open a serial console at 115200 baud (8N1, no flow control), power on the router, and interrupt the boot sequence when prompted. Assign a static IP (e.g., 192.168.1.2) to your PC's Ethernet interface, configure ipaddr and serverip in U-Boot, load the initramfs recovery image via tftpboot, and flash the permanent sysupgrade image from within temporary OpenWrt.

3. Post-Flash Setup: LuCI, AdGuardHome & WireGuard VPN

After OpenWrt boots for the first time, the router defaults to 192.168.1.1 with no root password set and Wi-Fi radios disabled by default for security.

  • Initial WAN & Security Configuration: Access LuCI in your browser at http://192.168.1.1, set a strong root password under System → Administration, enable the 2.4GHz and 5GHz wireless radios with WPA2/WPA3-SAE encryption, and configure your WAN interface (DHCP or PPPoE with VLAN tagging if required by your fiber ONT).
  • Network-Wide Ad Blocking (AdGuardHome): Update package lists via opkg update, install adguardhome (ensure sufficient flash space or use extroot/USB storage if needed), and configure dnsmasq to forward DNS queries on port 53 to AdGuardHome's listening port (e.g., 5353). This blocks trackers and ads across all connected devices without client-side apps.
  • WireGuard VPN Tunneling: Install luci-proto-wireguard and wireguard-tools. Create a new WireGuard interface under Network → Interfaces, generate your public/private keypair, import your VPN provider's peer endpoint configuration, and assign the interface to the WAN firewall zone with masquerading enabled to route home traffic securely.

06Setup OpenWrt (5 Operating Modes)

⚙️ OpenWrt Configuration Master Guide

Once OpenWrt is installed, your router is no longer locked to a single ISP topology. Depending on your home network layout, you can configure the device in any of five primary operating modes directly from the LuCI web interface:

1. Standard Router Mode Connects via WAN Ethernet to your primary modem/ONT using DHCP or PPPoE, providing NAT, firewalling, and local DHCP.
2. Dumb Access Point (AP) Mode Disables DHCP and firewall routing so the device extends an existing wired router's LAN without double NAT.
3. Hotspot / WISP Router Joins an upstream Wi-Fi network as a wireless client (WWAN) while broadcasting your own isolated private subnet.
4. Wireless Extender / Repeater Uses Relayd or 802.11s/WDS to extend Wi-Fi coverage across dead zones on the same broadcast domain.
5. USB Tethering Mode Shares mobile 4G/5G internet from an Android or iOS smartphone connected to the router's USB port as a primary or failover WAN.

09Common Troubleshooting & FAQ

Why does my SSH connection return "Connection Refused"?

Stock firmware disables SSH by default until unlocked. Confirm your PC is plugged into a LAN port (not WAN), verify you can ping 192.168.29.1, and double-check that your stock firmware version falls within the supported range in Section 02. If the password trick fails, proceed to the breeze.sh or WebUI downgrade step.

My serial UART console shows garbled text or stays blank

Garbled characters almost always indicate an incorrect baud rate—verify your terminal is set to 115200 8N1 with hardware/software flow control turned off. If the console is completely blank, swap the TX and RX jumper wires and verify a solid GND connection.

Can I revert back to stock firmware after installing OpenWrt?

Returning to stock firmware requires a full backup of your original MTD partitions (including bootloader and wireless calibration data) taken prior to flashing. Always back up your stock partitions over SSH or UART before writing any custom image.
